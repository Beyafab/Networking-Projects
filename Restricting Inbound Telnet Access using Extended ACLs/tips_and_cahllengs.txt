# LAB 61 - TIPS AND CHALLENGES

Topic:
Restricting Inbound Telnet Access Using Extended ACLs

Purpose:
This file contains practical tips, common mistakes, troubleshooting steps,
and important concepts learned while completing Lab 61.

1. UNDERSTAND THE TRAFFIC FLOW

---

The important traffic flow is:

R3 Loopback
|
| Telnet TCP/23
v
R1 VTY Lines

The ACL is not being applied to the serial interface.

Instead, it is applied directly to the VTY lines:

```
line vty 0 4
access-class TELNET-IN in
```

This is one of the most important concepts in this lab.

2. REMEMBER WHAT PORT 23 MEANS

---

Telnet uses TCP port 23.

Therefore, the ACL uses:

```
permit tcp host 10.10.10.3 any eq 23
```

The important parts are:

```
tcp      = Layer 4 protocol
host     = one specific source IP
any      = any destination
eq 23    = destination TCP port 23
```

## 3. DO NOT CONFUSE ACCESS-CLASS WITH IP ACCESS-GROUP

For VTY access:

```
line vty 0 4
access-class TELNET-IN in
```

For an interface ACL:

```
interface serial 0/0
ip access-group ACL-NAME in
```

They are not interchangeable.

access-class controls access to the VTY lines.

ip access-group controls traffic entering or leaving an interface.

4. ACL RULE ORDER MATTERS

---

Cisco ACLs are processed from top to bottom.

For example:

```
permit tcp host 10.10.10.3 any eq 23
deny tcp host 10.20.20.3 any eq 23
permit tcp host 10.30.30.3 any eq 23
```

Cisco checks the first matching statement.

Once traffic matches an ACL statement, processing stops for that packet.

5. THE IMPLICIT DENY

---

Every ACL has an implicit deny at the end.

Conceptually:

```
deny ip any any
```

This means traffic that does not match an explicit permit statement may
be denied.

This is particularly important when creating ACLs.

Always think about what traffic your ACL permits AND what traffic it
might unintentionally block.

6. COMMON MISTAKE: WRONG SOURCE IP

---

When testing from R3, make sure you use the correct source interface.

For example:

```
telnet 172.16.1.1 /source-interface loopback 10
```

should generate traffic from:

```
10.10.10.3
```

Similarly:

```
/source-interface loopback 20
```

should generate traffic from:

```
10.20.20.3
```

## 7. COMMON MISTAKE: FORGETTING THE ROUTE

The router must know how to reach the loopback networks.

R1 uses:

```
ip route 0.0.0.0 0.0.0.0 serial 0/0 172.16.1.2
```

This allows R1 to send unknown destinations toward R3.

Check the routing table with:

```
show ip route
```

## 8. COMMON MISTAKE: SERIAL INTERFACE DOWN

If the serial connection is not working, check:

```
show ip interface brief
```

You want to see something similar to:

```
Serial0/0    172.16.1.1    YES    manual    up    up
```

If the interface is administratively down:

```
interface serial 0/0
no shutdown
```

## 9. DCE CLOCK RATE

The DCE side of the serial connection needs to provide clocking.

In this lab R1 is the DCE side:

```
clock rate 2000000
```

If you are unsure which side is DCE, check:

```
show controllers serial 0/0
```

Look for the DCE designation.

Do not automatically configure clock rate on both routers.

10. TEST BASIC CONNECTIVITY BEFORE TESTING THE ACL

---

Do not immediately troubleshoot the ACL if Telnet fails.

Use this order:

Step 1:
Check interfaces.

```
show ip interface brief
```

Step 2:
Test the serial connection.

```
ping 172.16.1.2
```

Step 3:
Test the loopbacks.

```
ping 10.10.10.3
ping 10.20.20.3
ping 10.30.30.3
```

Step 4:
Test Telnet without worrying about ACL counters.

Step 5:
Apply and test the ACL.

Step 6:
Check the ACL counters.

```
show ip access-lists TELNET-IN
```

## 11. VERIFY THE VTY CONFIGURATION

Check:

```
show running-config | section line vty
```

You should have:

```
line vty 0 4
 password CISCO
 login
 access-class TELNET-IN in
```

## 12. VERIFY THE ACL

Use:

```
show ip access-lists TELNET-IN
```

You should see rules similar to:

```
permit tcp host 10.10.10.3 any eq telnet
deny tcp host 10.20.20.3 any eq telnet
permit tcp host 10.30.30.3 any eq telnet
```

## 13. ACL MATCH COUNTERS ARE VERY USEFUL

After testing Telnet, check:

```
show ip access-lists TELNET-IN
```

The match counters tell you whether traffic actually reached each
ACL statement.

Example:

```
10 permit tcp host 10.10.10.3 any eq telnet (2 matches)
20 deny tcp host 10.20.20.3 any eq telnet (1 match)
30 permit tcp host 10.30.30.3 any eq telnet (2 matches)
```

If the counter stays at zero, investigate:

* Wrong source IP
* Wrong ACL
* ACL not applied
* Wrong VTY line
* Routing problem
* Telnet not reaching the router

14. CHALLENGE: WHY DOES LOOPBACK20 FAIL?

---

This is intentional.

The ACL contains:

```
deny tcp host 10.20.20.3 any eq 23
```

Therefore, when R3 initiates a Telnet connection using Loopback20 as
the source, R1 sees:

```
Source:      10.20.20.3
Protocol:    TCP
Destination: R1
Port:        23
```

The traffic matches the deny statement.

The connection is therefore refused.

15. CHALLENGE: WHY DO LOOPBACK10 AND LOOPBACK30 WORK?

---

Because they match explicit permit statements:

```
permit tcp host 10.10.10.3 any eq 23
```

and:

```
permit tcp host 10.30.30.3 any eq 23
```

Therefore their Telnet connections are allowed.

16. CHALLENGE: WHAT IF THE ACL IS APPLIED TO THE SERIAL INTERFACE?

---

This would be a different design.

For example:

```
interface serial 0/0
ip access-group TELNET-IN in
```

This would filter traffic entering the interface.

The lab specifically wants the ACL applied to the VTY lines:

```
line vty 0 4
access-class TELNET-IN in
```

Remember the distinction for the CCNA exam.

17. CHALLENGE: WHAT HAPPENS IF YOU REMOVE THE ACL?

---

If you remove:

```
access-class TELNET-IN in
```

from the VTY lines, the ACL is no longer controlling VTY access.

The ACL itself may still exist in the configuration.

To remove the ACL from the VTY lines:

```
line vty 0 4
no access-class TELNET-IN in
```

## 18. CHALLENGE: WHAT HAPPENS IF YOU DELETE A PERMIT RULE?

Suppose you remove:

```
permit tcp host 10.30.30.3 any eq 23
```

Loopback30 will no longer match an explicit permit.

Because ACLs have an implicit deny at the end, the connection may
therefore be rejected.

19. USE REMARKS TO DOCUMENT ACLS

---

Remarks make ACLs easier to understand:

```
remark Permit Telnet From Host 10.10.10.3
```

They are especially useful in larger production configurations.

Good documentation helps other engineers understand why a rule exists.

20. REAL-WORLD SECURITY LESSON

---

Telnet is useful for learning the behavior of VTY access control, but
Telnet is not appropriate for secure production administration because
it does not provide encrypted management sessions.

For real network administration, SSH should normally be used.

The ACL concept remains important because the same idea can be used to
restrict management access to specific source networks or hosts.

21. CCNA EXAM MEMORY TRICK

---

Think:

```
VTY = remote login

access-class = control who can access VTY

interface ACL = control traffic through an interface

Telnet = TCP/23

SSH = TCP/22

ACL = top-to-bottom processing

Implicit deny = at the end
```
